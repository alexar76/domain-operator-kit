Sell domains to AI agents.

An agent can build and ship an app. This kit lets it take the next step: get a signed price for a name, register it to its real owner, set the DNS and connect it to Vercel. You run the seller with your own registrar account, your wallet and a fixed markup.

The sale

From a name to a working site, in four calls

The same steps whether the buyer is an agent with an MCP client or an app built on the JavaScript client. Nothing irreversible happens before the payment settles.

01

Quote

Free and signed: availability, the registrar's cost, your markup and the total, valid for five minutes. Agents ask your node directly or through an AIMarket hub.

02

Order

Sent straight to you, never through a hub: the registrant's contact, the accepted terms and the owner's public key, which signs every later request.

03

Pay

One x402 payment in USDC on Base, into your wallet. It settles before the registration; a registrar's definite refusal is refunded to the payer.

04

Deliver

Registered for one year with a receipt signed by your node. Then DNS records and, if the buyer wants, a Vercel project — all owner-signed.

The rails

      
What connecting to the rails gives a domain operator

      

        
Found by agents
Your node announces domains.quote@v1 to an AIMarket hub. After an automated admission check, agents searching the federation for a domain get your quotes.

        
Seller-direct payment
x402 moves USDC from the buyer's wallet to yours. The hub routes the search, never the money, and takes no commission.

        
Answers anyone can verify
Quotes, responses and receipts are signed with your node's Ed25519 key. Buyers pin that key through a catalogue before they spend.

        
Private where it matters
Contacts, payment authorizations and DNS changes go straight to the seller. A hub only ever sees public quotes.

Failure first

    
Built for interrupted operations

    
Registrars time out, payments land late, processes restart. The kit never submits a registration twice, and a proven non-delivery is refunded to the payer.

    

      
Durable order identity
Changed input cannot reuse an existing order. A wallet signature binds the payment to the order and the owner key.

      
No blind retries
A lost payment or registrar response goes to reconciliation with the original evidence, never to a second submit.

      
Refunds for proven non-delivery
Refunds go back to the paying wallet from a capped refund wallet. An ambiguous outcome stays pending until it is proven.

      
Private management
Owner requests and seller answers are Ed25519-signed; stored documents are AES-256-GCM. Registrar autorenew is off.

    Run it
    
      
    From an empty server to a public demo seller
    
      
    Node.js 22.13+ or Docker, and a domain for the node. With DOMAIN_MODE=auto it publishes a demo like this one — real availability, orders refused — and starts selling on the first restart after every live setting is in. /healthz names what is still missing, never the values.
    
      
    
        Quickstart
        Operator guide (RU)
      
    
    
    
    
    # 1. the kit, its tests and the simulated lifecycle
git clone https://github.com/alexar76/domain-operator-kit.git
cd domain-operator-kit
npm ci --ignore-scripts && npm test && npm run demo

# 2. a public demo seller: DOMAIN_MODE=auto,
#    DOMAIN_PUBLIC_URL=https://domains.you.example
cp .env.example .env && nano .env
docker compose up -d --build

# 3. what a buyer's client sees, and what live still needs
DOMAIN_ALLOW_DEMO=1 node bin/domain-rails.mjs check http://127.0.0.1:9495
curl -s http://127.0.0.1:9495/healthz

# 4. the federation node's config, to be listed on hubs
node bin/domain-rails.mjs node-toml https://domains.you.example \
  https://node.you.example http://127.0.0.1:9495 > node.toml

# 5. this page and the example desk, next to your node:
#    docs/landing/ is static — serve it at / and /desk/
