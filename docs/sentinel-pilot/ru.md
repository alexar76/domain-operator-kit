# Sentinel: деплой и домен

**Результат:** домен, DNS, HTTPS и API проверены успешно; повторное списание — $0.
Сайт: [sentinelproof.click](https://sentinelproof.click/). Отчёт приложения имеет
отдельное ограничение ATLAS, описанное ниже.

## Что проверяем

Фабрика ранее создала Sentinel и разместила его на Vercel. В этом тесте агент
повторно разворачивает ту же версию, покупает `sentinelproof.click` в аккаунте
владельца Porkbun и направляет домен на существующий проект Vercel.
Porkbun предоставляет домен и DNS; приложение остаётся на Vercel.

## Бюджет и доступы

Разрешена одна регистрация на год, не дороже $3. Фактическая покупка стоила
$1.54; баланс изменился с $10 до $8.46. Автопродление отключено.
Цена продления в полученной котировке — $10.81; перед будущим продлением её
нужно проверить снова. Домен оформляется с существующими контактами аккаунта,
с включённой WHOIS privacy. Возможное подтверждение email выполняет владелец.

Production-ключи Porkbun читаются из
`~/.config/domain-kit/porkbun/production/api-key` и `secret-key`, права `0600`.
Vercel-токен используется только на сервере фабрики через SSH и не копируется
на компьютер. GitHub не участвует.

## Запуск из корня aicom

```bash
node domain-kit/scripts/sentinel-live-pilot.mjs preflight
node domain-kit/scripts/sentinel-live-pilot.mjs deploy
node domain-kit/scripts/sentinel-live-pilot.mjs run
```

`preflight` вызывает официальный dry-run без списания. Его используют до
первой покупки: после регистрации имя закономерно перестаёт быть свободным.
`deploy` создаёт один повторный деплой, затем на следующих запусках проверяет
его состояние. Во время сборки нужно дождаться готовности и повторить команду.
`run` допускает покупку только после успешной проверки сайта и `/api/health`.
Повторный `run` использует сохранённый чек, не создаёт новый деплой и не
покупает домен заново. Код выхода `2` означает ожидание DNS или HTTPS.

После настройки DNS сценарий автоматически ожидает готовности: пауза между
проверками — 20 секунд, окно ожидания — 10 минут (уже начатая сетевая проверка
завершается со своим тайм-аутом). Статусы: ожидание DNS, сертификата, HTTPS,
приложения или ответа провайдера. `ready` выставляется только после успешных
проверок домена, DNS, сертификата, страницы и API с исправной базой данных.
Текущий статус сохраняется в `data/sentinel-live/setup-status.json`.
После истечения окна статус остаётся ожидающим; процесс завершается с кодом `2`.
Продолжить только настройку, без обращения к покупке:

```bash
node domain-kit/scripts/sentinel-live-pilot.mjs verify
```

После завершения процесса фонового опроса нет: продолжение запускается этой
командой либо внешним планировщиком. Ошибки доступа требуют внимания оператора.

## Восстановление и критерии успеха

Зашифрованное состояние и журнал операций находятся в
`domain-kit/data/sentinel-live/`, вне Git. Не удалять их для повторной попытки.
При потере ответа регистратора повтор используется с тем же ключом операции.
После 23 часов неизвестный результат требует ручной сверки, а не новой покупки.
Файл `pilot.lock` предотвращает одновременные запуски; после аварии сначала
проверь, что записанный процесс действительно завершился.

Успех: Vercel подтверждает домен и DNS, новый HTTPS-адрес открывает Sentinel,
API возвращает успешный health-check, повторный запуск не изменяет баланс.
Проверка получения safety report в браузере фиксируется отдельно: доступность
домена сама по себе не доказывает работоспособность внешних источников данных.

Это ограниченный пилот для одного проекта и домена, а не готовая услуга
регистрации доменов третьим лицам.

## Найденное ограничение приложения

На прежнем адресе Vercel и на новом домене браузерный запрос для Берлина вернул `UNKNOWN`:
платная возможность ATLAS `atlas.situation.brief@v1` недоступна в текущем
бесплатном режиме. Дополнительной оплаты ATLAS не было. Это отдельный
незакрытый дефект пользовательского сценария, не ошибка покупки или DNS.
